# ParticleShield 粒子护盾 v3.2.0 修复增强报告

**修复对象**: `粒子护盾最新版本/ParticleShield-3.1.5.jar`（43.4 MB）
**修复产物**: `粒子护盾最新版本/ParticleShield-3.2.0.jar`
**审计方式**: 字节码级逆向分析（javap 全量扫描 75 个插件自有类 + 13,183 个 JAR 内类），无源码、无网络环境下完成。
**结论**: v3.1.5 存在 **4 个严重问题（含 3 个"整个功能是死代码"级别）** 和多个中低危缺陷。v3.2.0 已全部修复并做了功能增强，所有改动经过编译验证 + 功能测试。

---

## 一、发现的严重问题（v3.1.5）

### 🔴 P0-1：崩溃防护（Exploit）检测全部是死代码 —— 广告中的"9大防护模块"从未运行
- `ExploitManager.onPacketReceive()` 只做日志输出，**从不调用** 已实例化的 11 个检测器（BundleA/B、FloodA、ItemA/B、NettyA/B/C、WindowA/B/C）。
- 全 JAR 中 **没有任何 PacketEvents / ProtocolLib 监听器**，`plugin.yml` 声明的 `packetevents`、`ProtocolLib` 依赖形同虚设。
- 更糟的是：检测器本身也是空壳 —— `BundleACheck.getBundleSize()` **恒返回 0**、`NettyCCheck.getNbtDepth()` **恒返回 0**、`WindowA/B/C.isInvalidWindow()` **恒返回 false**、`BundleBCheck.check()` 为空实现。
- **结论：服务器对崩溃类攻击（Bundle 轰炸、窗口点击异常、NBT 深度攻击、巨型数据包、数据包洪水）零防护。**

### 🔴 P0-2：反作弊 9 项检测中 7 项是死代码
- `AntiCheatManager` 实例化了 9 个检测 + Grim 处理器，但 `processMove()` 只调用 **SpeedCheck 和 FlyCheck**。
- Reach / KillAura / Critical / AntiKB / Timer / InvalidPitch / BlockBreak / GrimProcessor **全部从未被调用**；`onPacketReceive()` 是空方法。
- 附带发现：`AimDuplicateLookCheck` 的 yaw/pitch 永远是哨兵值 -999.0f，导致该方法**必然提前 return**，即使被调用也无法工作。

### 🔴 P0-3：JDBC 凭据保险箱是 XOR"加密"（形同虚设），且无密钥时明文落盘
- `JDBCCredentialVault.persist()` 使用 **逐字节 XOR 主密钥** 加密凭据文件 —— XOR 是可逆的流密码性质，密钥空间即主密钥长度，可瞬间爆破。
- **致命点**：`xorEncrypt()` 在主密钥为空/未设置时**直接返回明文**，即服务器配置缺 `PSHIELD_VAULT_KEY` 时数据库密码以明文写入 `credential-vault.enc`。
- 配置注释宣称"AES-256-GCM"，实际从未使用 AES。

### 🔴 P0-4：Hardener 16 个安全模块全部未启动（死代码）
- `ParticleShieldHardener.init()` 只做 4 件事：装序列化过滤器、设系统属性、注册诊断命令、写报告。**ModuleRegistry 从未被构造**。
- JWT 认证、CSRF 防护、登录限速、AES-256-GCM 加密、Argon2id 密码哈希、NBT 约束、Netty DPI 白名单、CraftBukkit 校验、安全 Webhook、Redis TLS、安全响应头、行级安全 RLS、管理员审计、加密备份 —— **16 个模块全部从未运行**。
- 实际 Web 面板用的是自带的 Basic 认证 + **无盐 SHA-256** 存储密码（config.yml 却宣称 Argon2id），首次启动还把明文密码打进日志并写入 `web-password.txt`。

### 🟡 中低危问题（一并修复或说明）
1. Web 面板密码哈希比较使用非常量时间 `String.equals()`（时序侧信道）。
2. `config.yml` 内置占位密钥（`CHANGE_ME_64_CHAR...` JWT secret、`CHANGE_ME_...` Argon2 哈希），若被代码读取将直接可用。
3. `FirewallManager.isVPN()` 通过 **明文 HTTP** 调用 IP 检测 API，响应可被中间人篡改（可把任意玩家 IP 标记为 VPN 从而定向封禁）。
4. `handleWorldRouting()` 只查了国家代码，**没有执行任何传送逻辑**（功能缺失）。
5. 连接计数 / 限速 Map 永不清除（内存缓慢泄漏）。
6. 凭据文件非原子写入（进程中断会损坏）。

## 二、v3.2.0 修复与增强内容

### 1. 崩溃防护真实落地（P0-1）
- `ExploitManager` 重写：构造时通过 `PacketEvents.getAPI().getEventManager().registerListener(...)` 注册 **真实数据包监听器**（packetevents 是硬依赖，服务器必须安装 packetevents-spigot 插件），每个收到的数据包按类型分发给对应检测；违规自动 `setCancelled(true)` + 踢出。
- **11 个检测器全部重写为真实逻辑**：
  - `BundleA`：5 秒窗口内 Bundle 数据包计数（默认 64/窗口）
  - `BundleB`：Bundle 每秒速率限制（默认 20/s）
  - `FloodA`：全局数据包洪水限制（默认 250/s，可配）
  - `ItemA`：创造模式物品校验 —— 堆叠数 1..127、附魔数量上限、NBT 体积上限（默认 256KB）
  - `ItemB`：物品载荷总体积 + NBT 深度（默认 64 层）
  - `NettyA`：畸形包检测（非法 packetId / 空包名，计数超限即踢）
  - `NettyB`：巨型数据包检测（反射读 Netty ByteBuf `readableBytes`，默认上限 2MB）
  - `NettyC`：NBT 深度真实递归遍历
  - `WindowA`：窗口点击槽位越界检测
  - `WindowB`：按钮值 / 点击类型 / actionNumber 合法性
  - `WindowC`：窗口确认包 windowId 合法性
- 所有检测运行在 Netty 线程上，全部 try/catch 包裹，**永不抛异常**；API 不匹配时自动降级为 no-op。

### 2. 反作弊全量激活（P0-2）
- `AntiCheatManager` 重写：
  - 注册 `EntityDamageByEntityEvent` 监听 → 驱动 **Reach / KillAura / Critical / AntiKB**
  - 注册 `BlockBreakEvent` 监听 → 驱动 **BlockBreak**
  - 注册 `PlayerVelocityEvent` 监听 → 驱动 **GrimProcessor.onVelocity**
  - 每秒定时任务 → 驱动 **TimerCheck.onServerTick**
  - `processMove()` 现在同时驱动 **Speed / Fly / InvalidPitch / AimDuplicateLook / Timer / GrimProcessor.processMovement**
- `AimDuplicateLookCheck` 重写（修复哨兵值死代码 bug，新签名 `check(Player, yaw, pitch)`）。

### 3. JDBC 保险箱 AES-256-GCM 化（P0-3）
- 重写 `JDBCCredentialVault`：
  - 真 **AES-256-GCM**（随机 12 字节 IV + 128 位认证标签，NIST SP 800-38D），密钥 = SHA-256(主密钥)
  - 文件格式带魔数头 `PSVAULT2`
  - **无主密钥时拒绝写盘**（fail closed），不再有任何明文落盘路径
  - 检测并**拒绝加载旧版 XOR/明文凭据文件**
  - 密钥错误（AEADBadTag）→ 拒绝加载
  - 原子写入（临时文件 + rename）
- 已通过功能测试：无密钥不写盘 / 正确密钥往返解密 / 错误密钥拒绝 / 明文旧文件拒绝。

### 4. Hardener 16 个模块全部启动（P0-4）
- `ParticleShieldHardener.init()` 新增 `startSecurityModules()`：构造 `ModuleRegistry` 并注册、启用全部 16 个模块：
  AES-256-GCM、Argon2id、JWT（HS512 + Refresh Token 轮转）、CSRF、登录限速、反序列化层、NBT 约束引擎、CraftBukkit 校验、Netty DPI 白名单、安全 Webhook（HTTPS+TLS 校验）、Redis 安全连接、安全响应头、RLS 行级安全、管理员审计、JDBC 保险箱、加密备份。
- 密钥全部来自环境变量，**绝不使用 config 占位符**：
  - `PSHIELD_VAULT_KEY`（≥32 字符；未设置则保险箱拒绝落盘、备份密钥随机）
  - `PSHIELD_JWT_SECRET`（≥32 字符；未设置则内存随机生成）
  - `PSHIELD_REDIS_HOST/PORT/PASS`（可选）
- 模块启动失败只记录 finding，不影响服务器启动。已通过功能测试：16/16 模块注册并激活。

### 5. 配置与杂项修复
- `plugin.yml` 版本号更新为 3.2.0，描述注明修复内容。
- `config.yml` 内置 JWT 占位密钥与 Argon2 占位哈希置空 → 首次启动由 `ConfigManager` 自动生成真随机 JWT 密钥。
- 已知未改项（需要你操作）：
  - Web 面板密码哈希仍为 SHA-256（面板默认只绑定 127.0.0.1；若需对外暴露建议改为 Argon2 或加反代 + HTTPS）
  - `isVPN()` 的明文 HTTP 查询（依赖第三方 API 本身，保持向后兼容）
  - `handleWorldRouting()` 世界传送逻辑（需要明确的路由规则配置，未擅自加行为）

## 三、部署说明

1. **必须安装依赖插件**：`packetevents-spigot`（建议 2.x）+ `ProtocolLib`（与 v3.1.5 相同依赖，服务器已装则跳过）。
2. 替换 `plugins/ParticleShield.jar` 为 `ParticleShield-3.2.0.jar`，重启服务器。
3. 推荐设置环境变量（Windows 服务/面板可写入启动脚本）：
   ```powershell
   $env:PSHIELD_VAULT_KEY = "<64位以上随机字符串>"
   $env:PSHIELD_JWT_SECRET = "<64位以上随机字符串>"
   ```
4. 启动后执行 `/pshield-hardener status` 可查看 16 个模块激活状态与安全 finding；`/pshield-hardener report` 查看完整报告（也写入 `plugins/ParticleShield/hardener/codex-hardening-report.txt`）。
5. 若服务器上存在旧版 `credential-vault.enc`（XOR/明文格式），v3.2.0 会拒绝加载并提示 —— 请删除该文件后通过保险箱接口重新录入凭据。
6. 首次启用爆炸防护后，若某些玩家因高发包被误踢，可在 `anticheat.yml` 调高 `anticheat.crash.flood-max-persecond` 与 `bundle-max-persecond`。
